# V21.2 test results and limitations

## Executed checks

- Full automated suite: **320 tests passed in 226.615 seconds**, including four new premium UI tests. Covers existing pricing, exports, revisions, approvals, permissions, customer documents, reports, backups and isolation. Existing synthetic file-handle ResourceWarnings do not fail the suite.
- New premium tests verify real metric values and favorite changes, saved/new editor asset exclusion, preservation of actual navigation destinations, viewer administration restrictions and exact original quotation filter markup.
- V21.2 Chromium suite: **seven scenario groups passed**, with no JavaScript errors. Captures 13 existing routes in both themes: dashboard, quotations, customers, customer workspace, customer documents, projects, project detail, reports, accounts, settings, approvals, notifications and Manage.
- The same suite checks no page-level horizontal overflow on those desktop pages, quotation layouts at 1920×1080, 1366×768, 1024×768, 768×1024 and 390×844, mobile navigation to Reports, real synthetic KPI counts, sidebar persistence/group expansion, protected editor exclusion and viewer restrictions. It also asserts dashboard/customer KPI icons do not overlap values.
- The existing V21.1 browser interaction suite passed: density and column preferences, bulk confirmation/cancel, clipboard, Back state, favorite/note save, unsaved-change protection, pre-send verification, grouped search and shortcuts, theme/responsive layouts and sidebar preferences.
- The original V21 browser suite passed, including customer activity and mobile editor checks.
- Final focused rerun: **10 UX/presentation/protection tests passed** after the visual corrections.
- Editor preview comparison against independently served **V21.1**: pixel-identical in light and dark mode at 1440×1000, excluding the 16px native Chromium scrollbar gutter. This compares the visible preview, not every editor state. The protected-file manifest separately verifies editor templates/scripts/styles, calculations, export code, approvals, quotation-list stylesheet and Windows launchers.
- Quotation filter fixture comparison and `git diff --check` passed. No dependency declaration or lockfile changes were needed.

Evidence is in `docs/v21.2-measurements/`. Before/after screenshots and deviations
from the approved mockup are linked in `docs/V21.2-UI-REVIEW.md`. Previous V21/V21.1
measurement directories are historical evidence for their respective releases.

## Known limitations and unexecuted checks

- Native Windows Server 2022, IIS, real SMTP delivery, production data, server backups and Windows PDF automation were **not tested or accessed**. The existing automated simulations pass; staging verification remains an operator step.
- The screenshot comparison verifies the visible quotation editor preview plus protected-source hashes; it is not an exhaustive pixel comparison of every editor dialog and responsive state.
- Not all historical version-specific browser scripts were rerun. The full Python suite and three relevant browser suites are the release checks.
- Dense tables retain horizontal scrolling on smaller viewports. Page-level overflow is checked, but not every possible user-generated name, localization or browser zoom setting is covered.
- Desktop cross-page screenshots use synthetic records with no submitted approval rounds; they correctly show zero required approvers rather than inventing demonstration approval dots. Existing approval behavior/tests remain unchanged.
- Browser-only column and list preferences retain their V21.1 account-scoped browser storage behavior; existing sidebar and theme preferences remain server-backed.
- No new financial metrics or performance claims are introduced. Existing report monthly fees and one-time fees remain separate, with no added annualization.
- Existing V21 build/version API compatibility metadata is retained; use the release commit and non-editor v21.2 footer to identify the UI source release.
