Server exports & full backups

These folders are accessed by the Workplace server, using the Windows account running Waitress/Python. They are not folders on the person’s browser or computer. For network shares use a UNC path and grant that server account both share and NTFS Modify permissions. Mapped drives may not exist in a service session.

Automatic PDF export · root quotation folder

Renderer: {{ renderer }}. Uses installed Edge/Chrome headless printing; no external conversion service. The browser must run under the service account and have a writable temporary directory.

Map each customer’s Quotation folder in their profile, or explicitly create one beneath this root. Missing mappings show “Customer export folder not configured”; there is no fallback customer destination. Files are saved under that customer folder in a separate quotation-ID subfolder to keep identical titles and different revisions apart. The saved title becomes the sanitized PDF filename. Later saves with the same title update that version’s PDF atomically. Customer reassignment and folder changes affect future exports; old files remain in place. Failures retain the saved quotation and allow Retry from document management.

Automatic daily full backups

Separate, non-nested destinations are required. Backups include the consistent SQLite database, all referenced attachments, private records, account hashes, permissions, registry, settings and audit history. They are sensitive: restrict folder access. Generated PDFs are derived outputs and are not attachments.

One successful backup per server-local calendar day; one weekly copy from the first successful backup of each ISO week. Missed days are not fabricated. Failed attempts retry hourly and are visible below. Retention removes only application-named archives inside its dedicated Cirrus-Workplace-full-backups subfolder after a successful backup.
